How it works

A ticket goes in. Only declarative artifacts come out.

The agent works in a live sandbox. At submission the environment is destroyed, the declared files are re-applied to a pristine one, and hidden checks run there.

Finding 1

Fixing a broken environment is far easier than building one.

Repair resolves at 80.2%. Greenfield at 52.1%. Same sign for all seven agents.

Finding 2

Deployments die at readiness, not at build.

Authoring a Dockerfile is static text generation, well represented in public corpora. Holding a rollout Ready needs closed-loop work against a live cluster.

Finding 3

We predicted health monitoring would be hardest. It is the easiest.

For the best agent: containerization 69.4%, orchestration 77.8%, health monitoring 90.9%. Seven of the nine tasks no agent resolved are single-image containerization tasks, where a wrong base image fails in ways that survive forty steps of iteration.

Validity

Four zero-intelligence arms. None resolves a single task.

The roster

The order is not a ranking.

Seven models, four providers, one four-tool loop, one fixed prompt, one graded episode per cell at a published seed. Switch the sort and the top changes.

Scope

A score says the agent produced infrastructure that satisfies the specification when redeployed from its declarative artifacts alone. It does not certify production security, predict behavior under live traffic, or cover cloud IaC.
